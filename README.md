# Calm — психологический сайт + Android-приложение

## Запуск в браузере
1. Установите Node.js (nodejs.org).
2. В папке проекта:
   ```
   npm install
   npm run dev
   ```
   Одна команда запускает и сайт, и сервер с базой данных.
3. Откройте http://127.0.0.1:5173

Публикация: `npm start` собирает сайт и отдаёт его вместе с API на порту 3001.

## Сборка Android-приложения (через Capacitor)
Проект обёрнут в [Capacitor](https://capacitorjs.com/) — тот же React-код работает как
нативное Android-приложение.

### Что потребуется один раз
- Android Studio (Hedgehog или новее) и Android SDK Platform 34.
- JDK 17.
- `JAVA_HOME` указывает на JDK 17, `ANDROID_SDK_ROOT` — на Android SDK.

### Готовый сценарий без аренды сервера (ngrok)
Ваш ПК становится сервером, ngrok даёт телефону публичный HTTPS-адрес к нему.

1. Поставьте ngrok CLI с https://ngrok.com/download (или `winget install Ngrok.Ngrok`).
2. Создайте бесплатный аккаунт на ngrok.com и выполните один раз:
   ```
   ngrok config add-authtoken ВАШ_ТОКЕН_С_САЙТА
   ```
3. Создайте `.env` (копия `.env.example`) и впишите:
   ```
   COOKIE_SECURE=1
   CORS_ORIGINS=https://localhost,capacitor://localhost
   ```
   Это разрешает APK ходить в API и держать сессию.
4. Установите зависимости и добавьте Android-платформу (один раз):
   ```
   npm install
   npm run android:add
   ```
5. Запустите сервер и туннель — в **разных** окнах:
   ```
   npm run server       # окно 1: Express + SQLite на :3001
   npm run tunnel       # окно 2: поднимет ngrok и само пропишет VITE_API_BASE
   ```
   Окно туннеля покажет адрес вида `https://abcd-12-34.ngrok-free.app` и
   автоматически положит его в `.env.production`.
6. Соберите APK — в **третьем** окне:
   ```
   npm run android:build      # vite build + cap sync android
   npm run android:open       # откроет Android Studio → Build APK
   # или сразу:
   npm run android:run        # на подключённом телефоне / эмуляторе
   ```
7. Пока окна `server` и `tunnel` открыты — приложение работает. Закроете — APK перестанет
   получать данные. Адрес ngrok меняется при каждом новом `npm run tunnel`, после чего нужно
   повторить шаг 6.

Для подписанного релиза в Google Play — `Build → Generate Signed Bundle / APK` в Android Studio.

### Важные моменты
- Адрес ngrok на бесплатном тарифе каждый раз новый. Перебилдите APK, если адрес изменился.
- Если хотите постоянный URL — переезжайте на бесплатный хостинг (Render / Railway / Fly.io)
  и впишите постоянный адрес в `VITE_API_BASE`.
- База SQLite у вас на сервере (на ПК), а не в приложении: APK общается с ней через API.
- Иконка/сплеш-скрин: `npx @capacitor/assets generate` из `resources/icon.png`.

## Редизайн (ноябрь 2026)
Дизайн переехал на единую тему в `src/styles/theme.css`:
- CSS-переменные цветов, радиусов, теней и тайминга анимаций.
- Тёмно-зелёный градиентный фон, светлые карточки — высокий контраст.
- Плавные `fadeInUp` / `shimmer` / `pulseGlow` анимации, учёт `prefers-reduced-motion`.
- Адаптивная шапка со скрытым скроллом на телефонах, поддержка `safe-area-inset-*`
  для Android/iOS WebView.

Страничные CSS остались рядом (`home.css`, `tests.css`, `quiz.css`, …) и теперь только
дополняют тему — повторы базовых правил удалены, стили больше не «перекрашивают» друг друга.

## ИИ-помощник (готовится)
Страница `/chat` и плавающая кнопка в правом нижнем углу уже есть — UI готов.
Сейчас отвечает заглушка. Чтобы подключить вашу обученную нейросеть:
1. Поднимите эндпоинт `POST /api/chat`, который принимает `{ message, history }` и
   возвращает `{ reply }`. Можно хостить рядом с Express-сервером (`server/index.js`).
2. В `src/pages/Chat.jsx` замените функцию `callAI` на запрос через `api.js`
   (например, добавьте `export const chat = (message, history) => request("POST", "/api/chat", { message, history })`).
3. Если модель умеет читать результаты тестов, передавайте в `history` или в системный
   промпт `fetchResults()` для вошедшего пользователя — это даёт контекст разговора.

## Аккаунты и безопасность (без изменений)
Регистрация по почте и паролю, вход, выход, подтверждение почты, сброс пароля,
смена пароля, удаление профиля.

- пароли хранятся только в виде хеша scrypt;
- cookie сессии с HttpOnly и SameSite=Lax; в базе — только хеш токена;
- после 8 неудачных попыток входа — блок на 15 минут;
- ответ «забыли пароль» одинаков для любой почты;
- при сбросе/смене пароля все другие устройства разлогиниваются;
- служебный заголовок обязателен (защита от CSRF).

## Письма
Скопируйте `.env.example` в `.env` и впишите SMTP вашего почтового сервиса.
Пока SMTP не настроен, письма не отправляются, ссылки печатаются в терминале
(`npm run dev`, строки `[mail]`).

## База данных
Таблицы: `accounts`, `sessions`, `email_tokens`, `results`. Баллы пересчитываются на сервере,
подделать результат запросом нельзя. Пользователь видит и удаляет только свои записи.
Для просмотра удобно DB Browser for SQLite (`server/data.db`).

Перед публикацией в интернет добавьте политику конфиденциальности, включите HTTPS
и не выкладывайте `data.db` в открытый доступ.

## Как добавить новый тест
Скопируйте любой объект в `src/data/quizzes.js`, поменяйте slug, вопросы, варианты и расшифровки.
Страница `/tests/<slug>` и карточка в списке появятся сами.

## Какие тесты есть
PHQ-9, GAD-7, WHO-5, Rosenberg, SWLS, Self-Compassion (short), IPIP-50, CBI (2 шкалы).
Источники и условия использования — внизу страницы каждого теста.

## Что проверено и не добавлено
- ASRS и K6: правообладатели просят разрешения на перевод.
- Mini-SPIN: источники расходятся в условиях использования.
- DASS-21: авторы просят не размещать для самостоятельного прохождения.
